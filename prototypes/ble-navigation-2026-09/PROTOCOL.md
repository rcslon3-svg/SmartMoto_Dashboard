# Данные и протоколы

## Пробуждение Android-моста возле CYD

`demo.cyd.companion` связывает CYD системным CompanionDeviceManager (CDM). Наблюдение CDM и фильтрованный BLE-скан с `PendingIntent` дают два источника событий, способных создать процесс приложения. Затем foreground-служба устанавливает GATT-соединение с CYD и обменивается кадрами протокола из `Protocol.java`. Диагност `demo.cyd.diagnostics` — отдельный APK/процесс и хранит свой журнал. Подробности в [ARCHITECTURE.md](source/cyd-companion-v2/ARCHITECTURE.md) и [HANDOFF.md](source/cyd-companion-v2/HANDOFF.md).

Событие `CDM_APPEARED` означает системное сообщение «рядом или подключено», а не доказательство конкретного радиопакета. Завершение процесса `killProcess` — не Force Stop. Автозапуск на Xiaomi проверялся в отдельных сценариях, но постоянная гарантия после перезагрузки, Force Stop или OEM-ограничений не заявляется.

## Google Maps → NavProbe

`MapsListener` получает уведомления через Android `NotificationListenerService`, оставляет пакет `com.google.android.apps.maps`, читает `Notification.extras` и восстанавливает `RemoteViews` для диагностического экрана. Для платы `NavPacket` извлекает дистанцию до манёвра из `TITLE` и до финиша из `SUB_TEXT`. Наблюдавшийся русский пример: `140 м` → `140m`, `2,8 км` → `2.8km`. Эти строки зависят от версии Maps и языка; это не официальный навигационный API и не координаты маршрута.

Белый значок из `largeIcon` (при отсутствии — из `right_icon` восстановленного `RemoteViews`) уменьшается до 48×48 и преобразуется в 1 бит на пиксель. Форма передаётся как bitmap; приложение не определяет семантический тип манёвра. Тайский текст улицы не передаётся, поскольку текущий шрифт платы его не содержит.

## NavProbe → Waveshare

Waveshare рекламирует BLE-имя `MotoNav-Round`, service UUID `a4aa19e0-c1ec-4f71-96fe-b5750060cc01`; write characteristic UUID оканчивается на `cc02`. Android начинает соединение после явного нажатия кнопки в NavProbe и использует foreground-службу типа `connectedDevice`. GATT-записи идут с ответом стека, кадры помещаются в исходный ATT payload 20 байт:

| Кадр | Формат | Значение |
| --- | --- | --- |
| `N` | тип, sequence, флаг изображения, длины двух ASCII-строк, строки | Начало нового состояния. |
| `I` | тип, sequence, номер 0–17, резервный байт, 16 байт | 18 частей bitmap 48×48 = 288 байт. |
| `E` | тип, sequence | Завершение; плата принимает состояние только после всех частей изображения. |
| `C` | один байт типа | Очистка навигации. |

Плата чередует навигацию и одометр раз в секунду, пока навигационное состояние активно. Без новых уведомлений последнее состояние остаётся. Навигация очищается при разрыве BLE, при отсутствии активного уведомления Maps или если `TITLE`/`SUB_TEXT` не содержат распознаваемые дистанции. Счётчик «Завершено записей по GATT» в старом NavProbe увеличивается только после `E`: очистка `C` его не увеличивает, поэтому неподвижный счётчик **не показывает причину пропажи навигации**. Запись GATT подтверждает приём BLE-стеком, не изображение на дисплее.

На текущем стенде GATT-сервис не требует спаривания и не аутентифицирует отправителя. Это прототип для доверенной среды, без гарантий против постороннего подключения.
