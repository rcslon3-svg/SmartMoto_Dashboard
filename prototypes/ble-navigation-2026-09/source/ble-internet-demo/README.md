# ESP32 → BLE → Android → веб-страница

Демо для ESP32-2432S028R / Cheap Yellow Display, Android 12+ и локального компьютера.
Плата определена по `C:\CODEX\Logic_v1\include\probe_config.h`: ILI9341, 320×240,
подсветка GPIO21. Старые проекты LOGIC и Nano не изменены.

## Что подготовлено

- `releases/cyd-internet-demo.apk` — установочный debug APK, пакет `demo.cyd.bridge`.
- `releases/cyd-demo-merged.bin` — полный образ ESP32, запись с адреса **0x0**.
- `firmware/` — самостоятельный проект PlatformIO / Arduino.
- `android/` — самостоятельный проект Android Studio, Java, minSdk 31, targetSdk 36.
- `server/` — Node.js 20+, без npm-зависимостей, веб-страница и HTTP API.
- `start-server.cmd` — запуск сервера двойным щелчком; завершение Ctrl+C в его окне.
- `flash-esp32.ps1 -Port COMx` — загрузка готового образа на явно выбранный порт.

## Быстрый запуск

1. Запустите `start-server.cmd`, если сервер ещё не работает. Страница компьютера:
   http://localhost:8787 . При `EADDRINUSE` порт уже занят; второй сервер не нужен.
2. Подключите телефон к той же Wi-Fi сети, что и компьютер. На момент подготовки
   адрес компьютера **192.168.1.101**, страница телефона http://192.168.1.101:8787 .
   IP может измениться после переподключения к сети. Не вводите localhost на телефоне.
3. Установите `releases/cyd-internet-demo.apk` на телефон. Можно скопировать APK
   по USB или скачать по ссылке «Скачать Android APK» на странице сервера.
4. Загрузите прошивку **на подтверждённую ESP32-2432S028R**. Прошивка заменит старый
   софт на плате. Не используйте порт Nano: CH340 сам по себе не подтверждает ESP32.
   В PowerShell из этой папки: `./flash-esp32.ps1 -Port COM4`, только если COM4 — CYD.
5. Откройте CYD Internet Demo на телефоне, введите `http://192.168.1.101:8787`.
   Сохраните адрес, нажмите «Привязать ESP32 по BLE», выдайте разрешения.
   После выдачи разрешений повторно нажмите привязку и выберите **CYD-Internet-Demo**.
   Если Bluetooth выключен, включите его и повторите действие.
6. Нажмите «Запустить мост». Телефон должен показать «Сервер OK»,
   экран платы — сообщение со страницы. Чтение выполняется раз в 3 секунды.
7. Нажмите SEND 1 / SEND 2 / SEND 3 на экране платы. Соответствующий счётчик
   на странице увеличится. Измените сообщение на странице и проверьте экран платы.

Если страница открывается на компьютере, но не на телефоне: проверьте одну Wi-Fi
сеть, изоляцию клиентов/гостевую сеть и разрешение входящего TCP 8787 в Windows
Firewall. Правила firewall автоматически не менялись. Локальный режим демонстрирует
передачу через телефон к компьютеру; мобильный интернет к частному адресу компьютера
доступа не даёт. Компьютер должен быть включён и не спать.

## Автоматический запуск

### Проверка без перезагрузки телефона — APK 0.3.0

Установите APK поверх предыдущего, один раз запустите мост и проверьте обмен.
Выключите плату, подождите минуту. В приложении нажмите «Тест автозапуска без
перезагрузки» → «Завершить приложение». Включите плату после закрытия приложения.

Тест явно останавливает BridgeService, дожидается onDestroy и затем завершает
собственный процесс. Он не меняет enabled, не удаляет Bluetooth-пару/association,
не выполняет force-stop и не регистрирует наблюдение заново. Если сервис не
остановился за 3 секунды, завершение процесса отменяется и причина видна в журнале.
Так проверяется запуск при появлении платы, а не восстановление после загрузки ОС.

Если уведомление вернулось ещё до включения платы, система восстановила службу
раньше тестового события; это не доказательство запуска по появлению платы.
Сохранённый журнал показывает время, источник запуска и PID процесса. Если связи
нет, откройте окно приложения и прочитайте журнал, не нажимая «Запустить мост».
Открытие окна само по себе мост не запускает.

Обновление APK 0.2.0: после выбора платы вызывается системный `createBond()`.
Привязка CompanionDeviceManager и Bluetooth-пара больше не обозначаются как одно
действие. В приложении показано фактическое состояние `getBondState()` из Android;
есть отдельная кнопка сопряжения уже выбранной платы. Подтверждение `createBond()`
само по себе не считается успехом: нужно дождаться `BOND_BONDED`.

Добавлен приём BOOT_COMPLETED после разблокировки телефона и MY_PACKAGE_REPLACED.
При включённом пользователем автозапуске восстанавливается наблюдение и запускается
BLE-мост. Если Bluetooth ещё выключен при загрузке, сервис ожидает его включения.
Журнал внизу приложения показывает получение события, регистрацию наблюдения,
запуск сервиса и готовность BLE. Обработчик загрузки — дополнительный механизм:
он запускает ожидание связи после загрузки телефона, а не только при появлении платы.
Ограничения производителя могут помешать доставке события/запуску; физическая
проверка обновления после перезагрузки телефона ещё требуется.

Устанавливайте 0.2 поверх 0.1 без удаления: адрес и привязка сохраняются.
Уже созданную вручную Bluetooth-пару удалять не нужно. Откройте приложение,
проверьте статус «сопряжено — подтверждено Android» и нажмите «Запустить мост».

Приложение использует системную привязку CompanionDeviceManager и наблюдение
за присутствием платы. PresenceService запускает foreground BLE-мост после
появления ранее привязанного устройства, когда переключатель `enabled` сохранён
кнопкой «Запустить мост». У сервиса постоянное уведомление и переподключение BLE.
После первого запуска окно можно закрыть: передача работает в фоне.

Это **автозапуск фоновой связи**, не принудительное открытие окна поверх других
приложений. Окно открывается нажатием уведомления. Кнопка «Остановить мост и
автозапуск» отключает оба режима. Системная «Остановить принудительно», отзыв
разрешений, энергосбережение производителя и перезагрузка требуют отдельной
проверки на конкретном телефоне; гарантии автозапуска после force-stop нет.
Для испытаний установите для приложения режим батареи «Без ограничений», если
телефон прекращает связь при погашенном экране.

## Ограничения демо

- Текст на дисплее: 1–48 печатных ASCII-символов, без `|`; кириллица не включена.
- Пока идёт запрос, кнопки серые. Новые нажатия в это время не сохраняются.
- Один запрос ждёт подтверждения и повторяется с тем же ID до трёх попыток.
  При недоступной сети постоянной очереди событий нет. `No ACK; result unknown`
  означает, что результат записи неизвестен: проверяйте страницу.
- На сервере запоминаются 256 ID для защиты от повторов и 30 последних событий.
  Счётчики и сообщение сохраняются в `server/data/state.json`.
- Предполагается одна плата и один телефон. BLE-протокол и локальный HTTP без
  аутентификации предназначены для тестовых данных в доверенной локальной сети.
- Калибровка резистивного тачскрина типовая. При смещении кнопок измените границы
  `map()` в `firmware/src/main.cpp`; Serial 115200 показывает сырые координаты.

## Сборка и проверки

Прошивка: `cd firmware`, затем `pio run`. Прошивка через PlatformIO:
`pio run -t upload --upload-port COMx`.

Android: открыть папку `android` в Android Studio, либо выполнить из неё
`./build-local.bat --gradle-user-home .gradle-home assembleDebug lintDebug`.
Локальный `local.properties` ссылается на установленный SDK. Для другого компьютера
Android Studio должна выбрать его собственный SDK. Нужна Java 17+; скрипт использует
JBR из установленной Android Studio. Gradle 9.2.1, AGP 9.0.1.

Сервер: из корня демо `node --test server/test.mjs`.

Проверено 21.09.2026:
- сборка ESP32 прошла; RAM 40 212 байта, Flash 1 157 141 байт;
- APK собран, Android Lint без ошибок (есть предупреждения о ресурсах/версиях);
- API: чтение/запись, повтор ID, валидация, запрет чужого Origin, сохранение после
  перезапуска проверены автоматическим тестом;
- запись сообщения через веб-страницу проверена в браузере;
- пользователь подтвердил ESP32 на COM4; esptool определил ESP32-D0WD-V3 rev 3.1;
- прежняя flash-память 4 МБ сохранена в `releases/esp32-before-demo-backup.bin`;
- демо записано на COM4, esptool подтвердил контрольную сумму;
- после записи Serial сообщил `DEMO ALIVE: BLE=0 subscribed=0 pending=0 heap=155476`:
  основной цикл работает, телефон ещё не подключён;
- реальная цепочка BLE с Android, тачскрин и фоновый автозапуск **пока не испытаны**.
  Android по ADB не обнаружен.

Для возврата к предыдущей прошивке: esptool `--chip esp32 --port COM4 write_flash
0x0 releases/esp32-before-demo-backup.bin`. Контрольные суммы файлов записаны
в `releases/checksums.json`. Резервная копия локальная и через веб-страницу не раздаётся.

Приёмка на устройствах: проверить три кнопки, изменение сообщения, выключение/
включение платы, погашенный экран телефона, отключение Wi-Fi, возврат сети,
остановку/повторный запуск сервера и отсутствие двойного учёта одного нажатия.

## Vercel и настоящий интернет

Тот же HTTP-контракт можно разместить в Vercel Functions с постоянным хранилищем
для счётчиков и сообщений. Текущий сервер сохраняет файл на компьютере; перенос
этого файла в Vercel Functions не заменяет базу данных. В публичном варианте нужны
HTTPS, аутентификация и атомарная дедупликация событий в хранилище. После этого
телефон может работать по мобильному интернету; в приложении меняется адрес сервера.
На существующие сайты и Vercel в этой задаче ничего не публиковалось.

## Протокол

BLE: сервис `6e400001-b5a3-f393-e0a9-e50e24dcca9e`; RX (телефон → плата, write with
response) оканчивается `0002`, TX (плата → телефон, notify) — `0003`.
Полные UUID имеют одинаковые остальные части.

Запрос: 11 байт, little-endian. Байт 0: версия 1, байт 1: операция 1=read/2=button,
байты 2–5: случайный boot/session ID, 6–9: sequence, байт 10: номер кнопки 0/1/2/3.
ID события HTTP: восьмизначный hex boot ID, дефис, sequence десятичным числом.

Ответ ASCII: `\rS|sequence|revision|count1 / count2 / count3|message\n`, ошибка:
`\rE|sequence|HTTP_ERROR\n`. Отправляется блоками не больше 20 байт, следующий
блок — только после GATT write callback. `\r` сбрасывает незавершённый старый ответ.
MTU negotiation не требуется. Плата принимает только ответ с ожидаемым sequence.

HTTP: `GET /api/state`, `POST /api/message {"message":"Hello"}`,
`POST /api/button {"button":1,"id":"a1b2c3d4-1"}`. Успешные запросы возвращают
текущее состояние. POST требует Content-Type application/json.
