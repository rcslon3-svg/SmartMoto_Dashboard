## Что завершено

- Новый проект `cyd-companion-v2/android`: модуль app (`demo.cyd.companion`, CYD Companion 2), модуль diagnostics (`demo.cyd.diagnostics`, CYD Диагност), общий исходный код в shared. Два разных UID/процесса, одна подпись.
- Мост: CDM association и наблюдение + независимый MAC-фильтрованный PendingIntent BLE scan. Единственный GATT foreground service, совместимый с прежней прошивкой и HTTP API. Источники запуска различаются. Нет автоматического открытия окна.
- Диагност: свой SQLite-журнал, защищённые signature broadcasts с копиями событий, своя отправка на сервер и JobScheduler. У моста НЕТ upload job в manifest, чтобы job не запускал мост во время проверки BLE.
- Завершение: явная команда мосту, Binder token → linkToDeath в диагносте → подтверждение сохранения последнего события ordered broadcast → Process.killProcess собственного PID. BRIDGE_PROCESS_DIED записывает диагност. Это не Force Stop, не полная имитация LMK. Команда может сначала создать отсутствующий процесс моста, и это отдельно записывается.
- Диагност самостоятельно читает PackageManager: FLAG_STOPPED, enabled, permissions, объявленный CDM service. Чужие CDM-привязки через публичный API Android 13 недоступны: мост читает getMyAssociations и передаёт снимок с временем. AssociationInfo.toString передаётся как сырой диагностический текст, без интерпретации нестабильных полей.
- Команды SNAPSHOT и ARCHIVE явно помечены как запускающие мост. Просмотр диагноста и его системные запросы не обращаются к мосту.
- Новый серверный модуль `cyd-companion-v2/server/telemetry.mjs` подключён из `ble-internet-demo/server/server.mjs`. `/api/v2/events`, `/diagnostics`, два отдельных APK download route. Старые данные и API сохранены.

Сначала прочитать существующий `ble-internet-demo/server/data/companion-v2-events.json`, если появился, и проверить доступность сервера. Не менять код без нового факта.
