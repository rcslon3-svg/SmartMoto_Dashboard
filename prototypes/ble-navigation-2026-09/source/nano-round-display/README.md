# Nano + круглый GC9A01, 240 × 240

Отдельная демонстрация для классического Arduino Nano ATmega328P, 5 В / 16 МГц. Каждую секунду переключаются страницы:

- ODOMETER / 000000 / km и TRIP / 888.0 / km;
- крупная стрелка направо / 500 m / Main St.

Чёрный фон, тонкая круглая рамка, светлые цифры и голубые акценты. Это демонстрационные данные: пробег не измеряется и не сохраняется, навигация с телефона не подключена.

## Подключение при отключённом питании

По предоставленному описанию модуль рассчитан на 2,8–3,3 В. Не подавать 5 В ни на VCC, ни на сигнальные контакты. Наличие защиты/преобразователя на этой плате не подтверждено.

Нужны стабилизированный источник 3,3 В с запасом по току (для стенда — модуль минимум на 150 мА) и преобразователь пяти сигнальных линий, например SN74LVC245A с питанием 3,3 В и допустимыми входами 5 В. Выход 3V3 неизвестного клона Nano не использовать как источник питания дисплея.

| Контакт дисплея | Подключение |
| --- | --- |
| VCC | 3,3 В от внешнего стабилизатора |
| GND | Общая земля Nano, стабилизатора и преобразователя |
| SCL / SCK | D13 через преобразователь 5 → 3,3 В |
| SDA / SDI / DIN | D11 через преобразователь 5 → 3,3 В |
| CS | D10 через преобразователь 5 → 3,3 В |
| DC | D9 через преобразователь 5 → 3,3 В |
| RST / RES | D8 через преобразователь 5 → 3,3 В |

SDA и SCL на данном модуле — сигналы SPI, не I²C. A4/A5 не используются. На фото видны семь контактов; порядок подключения проверять по маркировке своей платы, а не по тексту продавца «8Pin». Если на фактической плате есть дополнительный BL/BLK, его схема по этим фотографиям неизвестна.

Для SN74LVC245A: VCC (20) → 3,3 В, GND (10) → GND, DIR (1) → 3,3 В, /OE (19) → GND. Направление A → B. D13 → A1 (2), B1 (18) → SCL; D11 → A2 (3), B2 (17) → SDA; D10 → A3 (4), B3 (16) → CS; D9 → A4 (5), B4 (15) → DC; D8 → A5 (6), B5 (14) → RST. Неиспользуемые A6–A8 подключить к GND, B6–B8 оставить свободными. Поставить 100 нФ между VCC/GND возле микросхемы и 100 нФ + 10 мкФ возле дисплея. Сверять номера с корпусом и меткой вывода 1. Питание Nano и источника 3,3 В включать совместно; Nano можно питать USB, а вход подходящего стабилизатора — от его 5V. Выход стабилизатора не соединять с выводом 3V3 Nano. Провода SPI желательно короче 10 см.

## Прошивка

Открыть именно папку `nano-round-display` как проект PlatformIO. Сборка: `pio run`. Загрузка: `pio run -e nano_old -t upload --upload-port COMx`, заменив COMx на фактический порт Nano. Если установлен новый загрузчик, использовать `nano_new`. Не выбирать порт ESP32.

Загрузка заменит программу в Nano: этот скетч показывает дисплей и **не управляет мотором**. D4–D7 оставлены свободными; прежний проект мотора находится в родительской папке. Мигание LED_BUILTIN здесь не применяется: D13 занят SPI.

В `src/main.cpp` меняются демонстрационные значения, интервал `kPageIntervalMs` и поворот `setRotation(0)` (варианты 0–3). Шрифты содержат латиницу; кириллица в этом демо не реализована.

## Проверка на столе

22 сентября 2026: обе сборки `nano_old` и `nano_new` прошли успешно. Flash: 23042 из 30720 байт. Статическая RAM: 917 из 2048 байт; дополнительно полоса выделяет 240 байт в куче, также требуется место для стека и служебных выделений библиотеки. На плату прошивка не загружалась, внешний вид и длительность отрисовки физически не проверены.

1. До подключения дисплея измерить питание: 3,3 В; проверить общую землю и направление преобразователя.
2. После загрузки должны появиться обе страницы с переключением раз в секунду.
3. Serial Monitor 115200 показывает `ODO render_ms=...` / `NAV render_ms=...`. Время отрисовки должно быть меньше 1000 мс. Компиляция сама по себе не подтверждает работу физического экрана.
4. Если экран светится, но пустой: проверить CS/DC/RST, D11/D13, питание и маркировку контактов. При нестабильном изображении сократить провода и попробовать `kSpiHz = 1000000`.

Используется полоса 240 × 8 бит (240 байт в динамической памяти) и строка RGB565 (480 байт). Полного кадрового буфера нет. Каждая полоса сразу заменяется новым изображением без отдельного стирания экрана; переход всё же последовательный, аппаратная синхронизация кадров отсутствует. Таймер через millis() учитывает переполнение. Отрисовка синхронная: перед объединением с мотором, которому нужны фазы через 5 мс, необходимо переработать планирование, а не просто скопировать оба loop().

Документация: [Adafruit GC9A01A](https://github.com/adafruit/Adafruit_GC9A01A), [SN74LVC245A — TI](https://www.ti.com/product/SN74LVC245A). Инструкции по питанию платы Adafruit не относятся автоматически к модулю Estardyn.
